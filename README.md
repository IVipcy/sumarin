# 要約チェッカーさまりん ✨

小4向けの要約（ようやく）評価アプリ。
光村図書 国語4年「**未来につなぐ工芸品**」（大牧圭吾）の200字要約を、ルーブリック（評価規準）に基づいて A/B/C の3段階で評価します。

## 評価対象

- **原文**：「未来につなぐ工芸品」（要点・必須要素・参考例をサーバー側に組み込み済み）
- **入力**：子どもが書いた要約のみ（目安 160〜200字）

## 評価規準（ルーブリック）

要約に、削ってはならない核心となる3つの必須要素がすべて入っているかを見ます。

| 必須要素 | 内容 |
|--------|------|
| ① 工芸品のよさ・現状（初め） | 工芸品には独自のよさがあるが、現在は衰退の危機にあること |
| ② 具体例からの一般化（中） | 職人の工夫や地域の知恵、環境への配慮などが詰まっていること |
| ③ 筆者の主張（終わり） | 魅力を理解し、生活に取り入れるなどして、未来へつないでいくべきだということ |

| 評価 | 姿 |
|------|----|
| A（十分満足） | 3つの必須要素がすべて含まれ、接続語などが適切で、1つのまとまった文章として160〜200字で書けている |
| B（おおむね満足） | 少なくとも「①現状・危機」と「③筆者の主張」の2点が含まれ、160〜200字を満たしている |
| C（努力を要する） | 具体例（奈良墨・南部鉄器など）の羅列に終始している／筆者の主張が抜けている／字数が大幅に過不足している |

字数の判定はサーバー側で行い、AIに渡しています（範囲内／少し過不足＝B上限／大幅な過不足＝C）。

対象文や規準を変えるときは `source-text.js`（要素・参考例）と `evaluation-criteria.js`（プロンプト）を編集します。

## ローカルで動かす

```bash
npm install
cp .env.example .env
# .env に OPENAI_API_KEY を設定
npm start
```

http://localhost:3000 を開く

## Render へのデプロイ

1. GitHub にリポジトリを push
2. [Render](https://render.com) で New → Web Service
3. リポジトリを選択
4. 環境変数 `OPENAI_API_KEY` を設定
5. Deploy

## 使い方

1. 書いた要約を入力する
2. 「評価する！」ボタンを押す
3. A/B/C評価・必須要素ごとのフィードバック・修正例が表示される
